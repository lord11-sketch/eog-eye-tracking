# Data formats

## Serial stream (firmware to host), 115200 baud, one sample per line

| Format | Example | Firmware | Rate |
|---|---|---|---|
| labelled | `H:8454,V:8120` | v1 (archive) | 50 Hz |
| csv2 | `8454,8120` | v2 (archive) | 250 Hz |
| csv3 | `8454,8120,123456789` | **v3 (canonical)** | 250 Hz |

Values are 14-bit ADC counts: 0-16383 over the default 5 V reference, nominally 0.305 mV
per count at the ADC pin (reference not measured). The EXG Pills are powered from 5 V, so
their output rests near mid-scale. Counts cannot be converted to microvolts at the
electrodes until the EXG Pill gain is confirmed. The third field of csv3 is the firmware `micros()` value at
the sample (unsigned 32-bit, wraps every ~71.6 min; `eog.io.MicrosClock` unwraps it).
`eog.io.parse_line` rejects anything else; `eog.io.LineStream` additionally discards the
first line after connecting, rejects out-of-range values and lines in a different format
from the one first seen, and counts every rejection.

## Run files written by `python -m eog live` / `replay`

`test_<NN>_<tag>_<CH>_<YYYYMMDD_HHMMSS>.csv` and a matching `.summary.json`, one pair per
channel. The same columns for every method:

| Column | Meaning |
|---|---|
| `Time_ms` | Sample-clock time, ms. Live: since the first sample. Replay: the source file's time. |
| `Raw_<CH>` | Raw ADC counts |
| `Filtered_<CH>` | Method output (counts) |
| `Baseline` | Tests 01-03: calibration median of the output (constant). Tests 04-07: the method's running baseline estimate, in raw counts. |
| `Detector_Input` | What the dead zone is compared with: `Filtered - Baseline` (01-03) or `Filtered` (04-07) |
| `Direction` | `LEFT`/`CENTER`/`RIGHT` or `UP`/`CENTER`/`DOWN` |
| `Velocity` | Windowed velocity, counts/s (0 for methods that do not use it) |
| `Mode` | `SACCADE` / `FIXATION` / `-` |
| `Blink_Status` | `START` / `VALID` / `INVALID` / `-` |

Samples consumed by the 3 s calibration are not written (as in the original scripts). Rows
are flushed every 10 samples and on exit, including Ctrl+C and port errors.

### Summary JSON

```
method, test_num, title, channel, axis, fs_nominal_hz, rate_compensated,
dead_zone_counts, hold_frames, calibration_samples, clock
samples, duration_s, sample_rate_hz
raw:            mean_counts, std_counts, range_counts
detector_input: std_counts, noise_sigma_counts, peak_to_noise_db,
                residual_drift_counts_per_min, ..._mv_at_adc_per_min, ..._uv_at_electrode_per_min
direction:      centre_pct, negative_pct, positive_pct, changes, dwell_*
legacy:         baseline_excursion_counts(_per_min), removed_component_ratio_db,
                non_transition_pct_last_100
counters:       saccade_samples, fixation_samples, saccade_sample_fraction,
                adaptation_samples, blink_count, blink_reset_samples   (as applicable)
units:          adc_bits, adc_vref_v_nominal, mv_at_adc_per_count, frontend_gain, ...
stream:         lines, samples, parse_failures, range_failures, format_changes, stop_reason   (live only)
```

Definitions are in `eog/metrics.py`; the `legacy` block holds the original metrics under
accurate names (`docs/methods-review.md`, section 2).

## Recorded (April) files

Per-test column layouts of the files in `data/recorded` are listed in `data/README.md`.
`eog.io.read_recording` reads both layouts; it needs only `Time_ms` and `Raw_H`/`Raw_V`.

## Replay result tables (`docs/results/`)

Regenerated by the commands in the top-level README.

| File | Produced by | Contents |
|---|---|---|
| `replay_verification.csv` | `python -m eog verify` | Per recorded file: agreement between the recorded output and the output of this package |
| `json_summary_recomputation.csv` | `python -m eog verify` | Recorded JSON fields against the same fields recomputed from the CSV |
| `replay_comparison_per_recording.csv`, `replay_comparison_summary.csv` | `python -m eog compare --include-variants` | Every method on every recording; mean and SD per channel |
| `timing_sensitivity.csv` | `analysis/timing_sensitivity.py` | Output change under 0-1 ms timestamp jitter |
